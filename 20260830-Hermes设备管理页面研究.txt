Hermes Studio 设备管理页面研究
================================================================================
日期: 2026-08-30
研究目标: 为什么 "设备互联" → "小方盒" 页面看不到 T5 设备
================================================================================

## 一、问题现象

在 Hermes Studio Web UI 中：
- 导航到 "设备互联" → "小方盒" 标签
- 显示 "0 台设备" 和 "暂无设备"
- 已连接并正常工作的 T5 设备（IP: 10.10.168.121）不显示在列表中

## 二、根因分析

### 2.1 Hermes Studio 设备发现协议

Hermes Studio 使用 **UDP 广播** 在局域网中发现其他设备：

```
网关 → 255.255.255.255:48640  {"type":"hermes.discover","version":1,"request_id":"<hex>"}
设备 (监听48630) → 网关:48640  {"type":"hermes.announce","version":1,...,"request_id":"<回显>"}
```

### 2.2 关键字段

hermes.announce 响应必须包含：
- device_id: 设备唯一ID (MAC十六进制)
- computer_name: 设备显示名
- http_port: HTTP服务端口
- endpoint_kind: 设备类型 ("mcu"/"web"/"desktop")
- hermes_web_ui_version / hermes_agent_version: 版本号
- request_id: 回显请求中的request_id

### 2.3 T5固件缺失

T5固件(v2.3.1)没有实现UDP设备发现响应器：
- 无UDP监听
- 不响应hermes.discover广播
- 设备管理页面依赖UDP发现来列出设备

## 三、解决方案 (已实现 v2.4)

### 3.1 代码修改

在 T5/XRS 固件中添加：

1. **UDP监听初始化** (`initUdpDiscovery`)
   - WiFi连接成功后初始化
   - 监听UDP 48630端口

2. **发现请求处理** (`handleUdpDiscovery`)
   - 在主循环中调用
   - 解析hermes.discover包
   - 响应hermes.announce JSON

3. **WiFi连接成功后自动调用**
   - 在 `connectWifi()` 中增加 `initUdpDiscovery()` 调用

### 3.2 修改文件

| 文件 | 修改 |
|------|------|
| hermes-t5/src/main.cpp | +94行 (UDP发现协议实现) |

## 四、验证结果

### 4.1 UDP发现功能测试

发送UDP发现广播，T5正确响应：

```

[ANNOUNCE] From ('10.10.168.121', 48630):
{
  "type": "hermes.announce",
  "version": 1,
  "device_id": "F008D1C931B4",
  "computer_name": "HStudio-XRS-31B4",
  "http_port": 80,
  "endpoint_kind": "mcu",
  "hermes_web_ui_version": "v2.0",
  "hermes_agent_version": "v2.0",
  "relay_url": "",
  "request_id": "6a939308",
  "active_device_id": "F008D1C931B4"
}
```

## 五、结论

1. **根因**: T5固件缺少UDP设备发现协议实现
2. **修复**: 添加 hermes.announce 响应器
3. **验证**: UDP发现广播后T5正确响应所有必需字段
4. **效果**: 设备现在可以在Hermes Studio的"设备互联"页面中被发现
